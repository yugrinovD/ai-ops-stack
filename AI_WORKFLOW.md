# AI workflow

Этот стек собран с использованием AI-ассистента, но с явными границами
ответственности и проверяемыми артефактами.

## Принципы

- AI предлагает изменения, человек принимает архитектурные решения.
- Секреты и код работодателя не передаются в модели и не попадают в репозиторий.
- Каждый AI-сгенерированный фрагмент проходит тесты, линтеры и ревью.
- Документация и ADR фиксируют не только «что», но и «почему».

## Как проверяется результат

```bash
make config   # docker compose config -q
make up       # реальный запуск
make smoke    # lmlog → gogate → Ollama
make smoke-fallback
```

Дополнительно в репозиториях:

```bash
(cd ../gogate && make test && make lint)
(cd ../lmlog && make test && make lint)
(cd ../ops-console && npm test && npm run typecheck)
```

## Что не делает AI

- не публикует секреты и ключи;
- не меняет чужие репозитории без ревью;
- не «угадывает» модель: тег запинен в `OLLAMA_MODEL`;
- не добавляет `OLLAMA_*` в `ops-console` — консоль не знает про Ollama.
